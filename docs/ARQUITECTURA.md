# Arquitectura pedagógica del curso

## Propósito de diseño

El curso debe enseñar algoritmos como una competencia de resolución de problemas y no como una colección de fragmentos de código.

## Estructura de una unidad

Cada unidad podrá contener:

```text
unidadXX-tema/
├── README.md
├── ejemplos/
│   ├── pseudocodigo/
│   ├── python/
│   ├── java/
│   └── javascript/
├── ejercicios/
└── retos/
```

No todas las unidades necesitan implementaciones en los tres lenguajes. Solo se incluirán cuando ayuden a comparar la idea algorítmica con su implementación.

## Progresión

### Fundamentos
Problema → algoritmo → representación → prueba.

### Control
Datos → decisiones → repetición → modularización.

### Procesamiento
Colecciones → matrices → texto.

### Algoritmos clásicos
Búsqueda → ordenamiento → recursividad.

### Análisis
Medición → crecimiento → complejidad.

### Estructuras
Pilas/colas → mapas/conjuntos → árboles → grafos.

### Estrategias
Divide y vencerás → greedy → backtracking → programación dinámica.

### Integración
Problemas abiertos → diseño → implementación → comparación → justificación.

## Evaluación práctica sugerida

Los retos deben valorar principalmente:

- comprensión del problema;
- corrección del algoritmo;
- claridad de la representación;
- pruebas realizadas;
- capacidad de explicar la solución;
- análisis de alternativas;
- calidad de la implementación cuando aplique.

## Regla editorial

Los ejemplos deben ser pequeños y explicables. Los proyectos integradores deben combinar conceptos previamente estudiados y evitar introducir dependencias innecesarias.
