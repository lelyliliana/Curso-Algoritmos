# Unidad 25 — Proyecto final

## Propósito
Integrar análisis, diseño, implementación, pruebas y evaluación de algoritmos en un problema suficientemente abierto.

# Proyecto — Optimizador de rutas y tareas

Diseña una aplicación que modele ubicaciones o tareas como una red y permita resolver varios problemas sobre ella.

## Requisitos mínimos

### 1. Modelo
Representa elementos y relaciones mediante una estructura adecuada.

### 2. Consulta
Permite determinar si existe conexión entre dos elementos.

### 3. Recorridos
Implementa y compara BFS y DFS para al menos una operación.

### 4. Búsqueda y organización
Incluye una colección de datos sobre la que se realicen búsquedas y, cuando corresponda, ordenamiento.

### 5. Análisis
Documenta la complejidad temporal esperada de las operaciones principales.

### 6. Pruebas
Incluye:
- casos normales;
- casos límite;
- entradas inválidas;
- casos sin solución.

### 7. Comparación
Selecciona al menos una operación que pueda resolverse de dos formas y compara las alternativas.

## Entregables
- descripción del problema;
- requisitos y restricciones;
- modelo de datos;
- pseudocódigo;
- diagramas cuando aporten claridad;
- implementación;
- conjunto de pruebas;
- resultados;
- análisis de complejidad;
- conclusiones;
- README reproducible.

## Lenguaje
Puedes implementar el proyecto en Python, Java o JavaScript. La elección debe justificarse según el proyecto y no cambia los criterios algorítmicos.

## Criterios de calidad
- corrección;
- claridad;
- trazabilidad entre problema y solución;
- pruebas;
- uso adecuado de estructuras;
- análisis de eficiencia;
- explicación de decisiones;
- documentación.

## Extensiones opcionales
- interfaz gráfica o web;
- visualización de grafos;
- lectura de datos desde archivo;
- persistencia;
- comparación automatizada de tiempos;
- nuevas estrategias de búsqueda.

## Cierre

> Un buen algoritmo no es solamente el que produce una respuesta: es el que puedes explicar, comprobar, comparar y mejorar.
