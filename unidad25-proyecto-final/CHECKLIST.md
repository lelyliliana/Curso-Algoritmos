# Lista de comprobación antes de entregar

## Problema
- [ ] El problema está claramente definido.
- [ ] El alcance indica qué no resuelve.
- [ ] Entradas, salidas y restricciones están documentadas.

## Diseño
- [ ] Existen pseudocódigos de los algoritmos principales.
- [ ] Las estructuras de datos están justificadas.
- [ ] Se consideró al menos una alternativa cuando era razonable.

## Implementación
- [ ] El proyecto puede ejecutarse siguiendo el README.
- [ ] No contiene rutas o configuraciones personales innecesarias.
- [ ] Los nombres ayudan a comprender la solución.

## Pruebas
- [ ] Hay casos normales.
- [ ] Hay casos límite.
- [ ] Hay casos inválidos cuando aplica.
- [ ] Se probaron escenarios sin solución cuando existen.
- [ ] Los resultados esperados están registrados.

## Análisis
- [ ] Se analiza tiempo.
- [ ] Se analiza memoria cuando es relevante.
- [ ] Las conclusiones no contradicen la evidencia.

## Documentación
- [ ] Otra persona puede reproducir el proyecto.
- [ ] Las limitaciones se declaran.
- [ ] Las decisiones importantes están explicadas.
